# Olist: продуктовая аналитика e-commerce на SQL

Пет-проект на открытых данных бразильского маркетплейса **Olist** (~100 тыс. заказов, 2016–2018).
Задачи сформулированы как письма от продакт-менеджера: «как у нас дела?», «возвращаются ли покупатели?» —
по каждой нужен ответ с цифрами и рекомендация.

**Стек:** PostgreSQL · DBeaver · SQL (CTE, оконные функции, когортный анализ) · Google Таблицы / matplotlib для графиков

## Главное
| | Находка |
|---|---|
| 📈 Рост | Январь–август 2018 к 2017: заказы **+140%**, GMV **+143%** (3,47 → 8,45 млн R$). Рост за счёт числа заказов — средний чек почти не изменился (+1,4%) |
| 🛒 Чёрная пятница | 24.11.2017 — 1 147 заказов против ~170 в обычный день (**×6,7**) |
| 🔁 Повторные покупки | Повторно покупают только **2,13%** покупателей; медиана до повторной покупки — 76 дней. 30% «вторых покупок» — заказы в течение суток (одна корзина, разбитая на заказы) |
| 💰 LTV | За 12 месяцев покупатель приносит **150–180 R$**, из них **96–98%** — в месяц первой покупки |
| 💡 Вывод | Бизнес держится на первых покупках. Вернуть покупателя у Olist мало рычагов, а прямой контакт есть с продавцами — рост через число и удержание продавцов (гипотеза) |

## Контекст бизнеса
Olist подключает небольшие магазины к крупным маркетплейсам Бразилии по одному договору. Товары продаются под витриной Olist Store, а продавец отправляет заказ через логистических партнёров Olist. После доставки покупатель получает опрос — отсюда таблица отзывов. **Клиент Olist — продавец**, доход — комиссия с продаж.

## Данные
[Brazilian E-Commerce Public Dataset by Olist](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce) (Kaggle). CSV в репозиторий не входят.

Таблицы загружены в PostgreSQL с короткими именами: `orders`, `customers`, `order_items`, `payments`, `reviews`, `products`, `sellers`, `geolocation`, `category_translation`.

Ключевые особенности данных, найденные по ходу:
- `customer_id` создаётся на каждый заказ, покупатель — это `customer_unique_id`;
- в `payments` несколько строк на заказ (карта + ваучеры) — суммировать без размножения строк;
- в 2016 году — единичные заказы, после августа 2018 — нет доставленных заказов (данные до 17.10.2018);
- при импорте через DBeaver отзывы с кавычками в тексте склеивались — `reviews` загружена через `psql \copy`.

## Как воспроизвести
1. Скачать датасет с Kaggle, загрузить CSV в базу PostgreSQL с именами таблиц выше; даты — тип `timestamp`.
2. Проверить загрузку: [`sql/00_check_import.sql`](sql/00_check_import.sql) (число строк по таблицам).
3. Задача 1: сначала `sql/01_0_views.sql` (создаёт VIEW), потом остальные `01_*` в любом порядке.
4. Задача 2: сначала `sql/02_1_*` и `sql/02_2_*` (создают VIEW), потом `02_3`, `02_4`.
